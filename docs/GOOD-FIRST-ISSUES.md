# Good First Issues · 新手可做的任务

> 本仓库处于固件普查阶段，前期任务大多不需要写代码。
> 认领方式：在对应 Issue 下留言「我来」，避免重复劳动。

---

## 文档类（无需写代码）

### G01 · 补一份 E01 固件样本
- 难度：★☆☆☆☆
- 门槛：有一台 ICON 2020 款车机
- 做法：车机「设置 → 关于本机」拍照，按 `docs/FIRMWARE-CENSUS.md` 样本表填写并提交
- 产出：一份样本；30 份即可进入阶段 1

### G02 · 补一份实车测试记录
- 难度：★★☆☆☆
- 门槛：能装 APK
- 做法：按 `docs/TESTING.md` 逐项验证，失败也要提交
- 关键：写清失败发生在哪个阶段

### G03 · 翻译 README 的关键段落
- 难度：★☆☆☆☆
- 做法：把固件普查和参与方式两段译成英文，便于上游与国际社区看到

### G04 · 补一份「E01 车机装第三方 APK 方法」文档
- 难度：★★☆☆☆
- 做法：整理 ICON 2020 款已知的安装途径（U盘 / ADB / 工程模式），写明各固件分支下的差异
- 价值：这是大量车友卡住的第一步

## 工具类（会脚本即可）

### G05 · 写一个固件信息一键采集脚本
- 难度：★★★☆☆
- 做法：把 `docs/FIRMWARE-CENSUS.md` 里的 ADB 命令封装成一个脚本，输出可直接粘贴的 Markdown 表格
- 价值：把样本提交门槛从「手工抄 10 项」降到「跑一条命令」

### G06 · 完善 `scripts/repack.sh`
- 难度：★★★☆☆
- 现状：当前为示意版，未实际验证
- 做法：在真实官方 APK 上跑通，补齐错误处理与参数校验
- **红线**：不得复制、导出或提交任何身份资产文件

---

## 代码类（需要 Android/Kotlin）

### G07 · 整理 Legacy 分支在 API 22 上的已知崩溃点
- 难度：★★★★☆
- 做法：静态扫描 + 实车验证，列出 API 22 上的不兼容调用（参考 v0.2.7 已修的 SwitchCompat 崩溃）
- 注意：通用层问题应同步提 PR 给上游

### G08 · 排查 USB 握手失败阶段
- 难度：★★★★★
- 前提：阶段 1 基线已建立
- 做法：定位失败在 USB 配置切换、iAP2 握手还是授权环节
